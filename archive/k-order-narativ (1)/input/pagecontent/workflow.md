This guide specifies a document, not a process. The lifecycle of an eReferral is a property of the system through which the document is exchanged — in the Czech setting it is carried by the system header, and its states, transitions and operations are described in the Standard of the eReferral System. The FHIR Bundle is assembled and signed at issue and does not change afterwards, see [Implementation notes](implementation-notes.html). Where the document is exchanged in a context other than the eReferral system, the process rules of that context apply.

Resources in the bundle have their own `status` elements, for example `Composition.status` or `ServiceRequest.status`, and they express the state of the document and of the request at the time of issue.

The [RequestStatus](https://hl7.org/fhir/R4/valueset-request-status.html) value set is not the state model of an eReferral and must not be presented as one, because its values and the states the eReferral system distinguishes do not match in either direction. The state of the eReferral is carried by the system header, see [Home](index.html), section The two parts of an eReferral. The same applies to the element `A.1.8.3 Document status`.
